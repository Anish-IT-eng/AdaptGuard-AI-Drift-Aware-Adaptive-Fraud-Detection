# AdaptGuard AI — Data Directory

This directory holds all raw and processed transaction data for the project.

## Structure

```
data/
├── raw/
│   └── transactions.csv          ← Simulator output (never modified)
└── processed/
    ├── transactions_none.parquet     ← No drift (E1 stable)
    ├── transactions_abrupt.parquet   ← Abrupt drift at day 90 (E2)
    ├── transactions_gradual.parquet  ← Gradual drift days 60–90 (E3)
    └── transactions_recurring.parquet ← Two drift events (E4)
```

## Data Source

This project uses a **synthetic dataset** generated by the
[ULB/Worldline Fraud Detection Handbook simulator](https://fraud-detection-handbook.github.io/fraud-detection-handbook/).

> No real customer transaction data is used. All records are fully synthetic.

### Simulator Configuration

| Parameter      | Value        | Description                        |
|---|---|---|
| `n_customers`  | 5,000        | Synthetic customer profiles        |
| `n_terminals`  | 10,000       | Synthetic merchant terminals       |
| `nb_days`      | 183          | Simulation span (~6 months)        |
| `start_date`   | 2023-01-01   | Simulation start                   |
| `r_fraud`      | 0.0084 (~0.84%) | Base fraud rate (highly imbalanced) |
| `random_state` | 42           | Reproducibility seed               |

**Expected output:** ~1.75M transactions, ~14,700 fraud cases.

## Schema

| Column          | Type      | Description                       |
|---|---|---|
| `TRANSACTION_ID` | int      | Unique transaction identifier      |
| `TX_DATETIME`   | datetime  | Transaction timestamp              |
| `CUSTOMER_ID`   | int       | Customer identifier                |
| `TERMINAL_ID`   | int       | Merchant terminal identifier       |
| `TX_AMOUNT`     | float     | Transaction amount (synthetic $)   |
| `TX_FRAUD`      | int (0/1) | Fraud label — **target variable**  |

## Generating the Data

```bash
# From the project root:
python experiments/run_experiments.py --experiment e1_stable
```

This will:
1. Run `src/data/simulator.py` to generate `data/raw/transactions.csv`
2. Apply `src/features/engineering.py`
3. Save to `data/processed/transactions_none.parquet`

## Drift Variants

| File                           | Drift Type    | When Injected         |
|---|---|---|
| `transactions_none.parquet`    | None          | —                     |
| `transactions_abrupt.parquet`  | Abrupt        | Day 90 (3× fraud rate) |
| `transactions_gradual.parquet` | Gradual       | Days 60–90             |
| `transactions_recurring.parquet` | Recurring   | Days 45 + 90           |

## ⚠️ Important Notes

- **Never shuffle** this data. Temporal ordering is essential for the prequential evaluation protocol.
- **Never modify `raw/`**. Feature engineering always starts from `raw/transactions.csv`.
- Drift injection is controlled and documented — all drift-start timestamps are known, enabling detection-delay measurement.
- The data directory is **not committed to version control** (see `.gitignore`). Generate locally before running experiments.
